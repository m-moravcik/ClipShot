# ClipShot 1.0.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship ClipShot 1.0.0, a public macOS menu bar app that copies every saved native screenshot to the clipboard, exposes the native save-folder and thumbnail settings, and moves old screenshots to the Trash, released through the same channels as VibeRes and Eject Guard.

**Architecture:** XcodeGen project with one app target and one Swift Testing target. `ClipShot/Core/` holds UI-free logic behind small protocols (preferences, file events, pasteboard, trash) so it is tested with fakes and temp directories; `ClipShot/UI/` holds SwiftUI views and the `@Observable` `AppModel` that wires Core to the popover, Settings and the menu bar icon. Updater, login item and design tokens are ported from VibeRes; the timer-driven menu bar animation is ported from Eject Guard.

**Tech Stack:** Swift 6 (strict concurrency complete, warnings as errors), SwiftUI `MenuBarExtra(.window)` + AppKit, XcodeGen, Swift Testing, Sparkle 2.10.0, FSEvents, ImageIO, `NSPasteboard`, `FileManager.trashItem`, `SMAppService`, `Synchronization.Mutex`.

**Spec:** `docs/superpowers/specs/2026-10-19-clipshot-design.md` (approved and revised 2026-10-19). Read it before any task.

**Version note (owner decision 2026-10-20):** the first public release is 0.9.0, not 1.0.0; screen recordings come in 1.0 (spec Addendum B).

**Reference repos (read-only):** VibeRes (project.yml, Makefile, scripts/release-signed.sh, scripts/make-appcast.sh, `.github/workflows/release.yml` for the release order and feed smoke check at lines 263-383, Updater*, LoginItem, DesignTokens, OnboardingView, ScreenshotHarness, check-localisation) and Eject Guard (Sources/App/StatusIcon.swift + GuardController.swift timer phases, DEVELOPMENT.md, release-notes/, About tab, `.release.env`). "Port X" means copy, rename VibeRes/Eject Guard to ClipShot, drop what ClipShot does not use, keep comments that still apply.

**Review findings folded in (2026-10-19):** plan verification, an AI audit and a motion review. Their reports drove the Review Focus, Task 0 decision table, retention safety, FSEvents choice, release order and the motion steps.

## Review Focus

1. **Folder changed to a place full of old screenshots (`Cmd+Shift+5` > Options > Documents)** - retention pauses and asks; nothing is trashed without a preview. Tests in Task 4 (`retentionPausesWhenFolderDiffersFromConfirmed`) and Task 7 (`folderChangeRaisesRetentionAttention`).
2. **Markup Done rewrites the file in place, or the marker lands after the file appears** - the edited image is copied; a late marker is still picked up. Tests in Task 5 (`copiesAgainWhenMarkupRewritesFile`, `copiesWhenMarkerArrivesAfterCreate`).
3. **Folder access denied, folder deleted or unmounted while running** - attention row appears and clears on its own once the folder is readable again. Tests in Task 5 (`unreadableFolderSetsAccessDenied`, `detectsFolderDeletedWhileWatching`, `recoversWhenFolderReappears`).
4. **Old screenshot duplicated in Finder or dropped in from AirDrop/download** - not copied, not retained-as-own. Tests in Task 3 (`skipsFinderDuplicateOfOldScreenshot`, `quarantinedFileIsNotScreenshot`).
5. **First minute: user pastes before the thumbnail is gone** - header hint explains it until the first copy, onboarding "Try it" proves it works. Test in Task 7 (`firstCopyHintShownUntilFirstCopy`).
6. **Screenshots from before ClipShot, or renamed ones** - never moved unless explicitly adopted; renamed = kept. Tests in Task 4 (`unknownFilesAreNeverMoved`, `renamedLedgerEntryIsKept`).

### Task 5: File events and copy coordinator

**Files:** Create `ClipShot/Core/FolderEvents.swift`, `ClipShot/Core/CopyCoordinator.swift`. Test: `CopyCoordinatorTests.swift`.

**Interfaces:**
- Consumes: Tasks 2-3, `Log`.
- Produces:
  - `protocol FolderEventSource: Sendable { func start(_ folder: URL, onEvent: @escaping @Sendable () -> Void) throws(WatchError); func stop() }`; `final class DirectoryEventSource` (`DispatchSource.makeFileSystemObjectSource` on an `O_EVTONLY` fd, mask `[.write, .delete, .rename, .revoke]`, state in `Mutex`). Spike F4/F5/F7: macOS writes every capture, including Markup Done, as a dot-temp file renamed to the final name, which fires the directory event; the marker lands 0-54 ms later, so every event is followed by rescans. FSEvents is not used: its events arrived 10-24 s late in the spike.
  - `enum WatchError: Error, Equatable, Sendable { case folderMissing(URL), accessDenied(URL), folderRemoved(URL) }`
  - `@MainActor final class CopyCoordinator { init(settings: CaptureSettings, events: any FolderEventSource, pasteboard: any PasteboardWriting, clock: @escaping @Sendable () -> Date, pollInterval: Duration = .seconds(1)); var isEnabled: Bool; private(set) var lastCopied: CaptureFile?; private(set) var watchError: WatchError?; private(set) var lastFailure: Date?; var onCopied: ((CaptureFile) -> Void)?; var onFailure: (() -> Void)?; func start(); func stop() }`
  - Every fresh screenshot observed (copy enabled or not) is recorded in `ScreenshotLedger` (init parameter `ledger: ScreenshotLedger`).
  - Behaviour: start and every re-target seed the decider with existing files; while disabled, events still seed (no catch-up on re-enable). An event lists the folder off-main (dot-files ignored); a fresh image file that is not yet a screenshot or not decodable is re-inspected at 250 ms, 1 s and 3 s. If the configured folder is missing, macOS saves to `~/Desktop` (spike F14): the coordinator raises `folderMissing` and watches `~/Desktop` meanwhile. Burst: copy in `created` order. Multi-display: `Cmd+Shift+3` writes one file per display within ~100 ms (spike F3); of `display`-type files created within 1 s of each other only the first (main display) is copied, all are recorded in the ledger. The poll (1 s) re-reads `settings.folder()`, re-targets on change, and while `watchError != nil` re-probes and restarts. A fresh screenshot that fails conversion or `writePNG` sets `lastFailure` and calls `onFailure`; logged as `copy failed ext=<ext>`.
